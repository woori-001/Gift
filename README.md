# 사은품 차감 검수

정산 당시 **정산내역서**와 현재 **로우데이터(전체정산관리)**를 건별로 대조해서, 정산 후 사은품이 지급됐는데 정산서에서 차감되지 않은 건(이중 지출)과 정산서에 빠진 건을 찾는 웹앱이에요.

- 엑셀 파일은 **브라우저 안에서** 읽어요. 원본 엑셀 파일 자체는 서버로 가지 않아요.
- 올린 파일의 내용(검수에 필요한 칸만, 고객명은 가려서)은 **회차별로 Supabase에 자동 저장**돼요. 다음에 들어와도, 다른 PC나 팀원도 이어서 할 수 있어요.
- 검수 결과와 실행 기록도 Supabase에 저장해요.
- 로그인은 이 앱 전용 계정(아이디/비밀번호)으로 해요. 계정은 관리자가 만들어요.

## 판정 기준

| 구분 | 조건 |
|---|---|
| ① 미차감 | 현재 로우가 `웨이브넷 지급`이고 금액이 있는데, 정산서의 `차감내역_사은품`이 그보다 적음. 차액이 환수 대상 |
| ② 정산서 누락 | 로우에는 있는데 올린 정산서 어디에도 없음. 일반·추가·환수로 나눠서 표시 |
| ③ 정산서에만 | 정산서에는 있는데 현재 로우에 없음 |
| ④ 금액 변동 | 약정·번들·동판·다른 차감 항목이 정산 후 바뀜. 과차감 포함 |
| ⑤ 확인 필요 | 로우 자체 이상. 유치자지급인데 금액 있음, 웨이브넷 지급인데 차감 부족, 동일 행 중복 |

**검수 대상**: 자점(협력점명이 `1.시흥영업팀`, `2.천안영업팀`처럼 번호+점으로 시작)은 로우·정산서 모두에서 빼고 검수해요.

**매칭 순서** (위에서 못 찾은 건만 다음 단계로)
1. `정산종류 + 가입서비스 + 상품명 + 상품옵션 + 개통일` + 고객명(`*`는 아무 글자). 이름이 달라도 협력점이 같으면 매칭하고 "고객명 다름" 표시
2. `정산종류 + 가입서비스 + 상품명` + 느슨한 이름 비교(괄호·`/메모` 떼고, `*` 하나가 여러 글자 대신 가능) → "개통일·상품옵션 변경" 표시
3. 가입서비스 번호 조각(`/`로 나뉜 것) 하나라도 같고 `정산종류 + 상품명`이 같으며, 이름(느슨하게)이나 협력점이 같으면 매칭 → "가입서비스 표기 다름" 표시
4. 가입서비스만 다르고 `협력점 + 정산종류 + 상품명 + 상품옵션 + 개통일`과 이름(느슨하게)이 같으면 매칭 (SKB 번호 끝자리 변경 등) → "가입서비스 번호 다름" 표시

- 가입서비스는 `(★상품권,문자)`·`(유심)` 같은 괄호 메모, `후첨부`·`선약`·`합` 같은 한글 메모, ★·공백·하이픈을 떼고 번호만 비교해요.
- 가입서비스가 비어 있는 건은 이름이 다르면 협력점만으로 엮지 않아요.
- 협력점명은 `★■◆○●` 같은 기호와 `(휴)`를 떼고 비교해요.
- 같은 내용의 행이 여러 줄이면 줄 수까지 1:1로 맞춰요.
- **누락**은 올린 정산서의 정산예정일(회차)에 해당하는 로우만 판단해요. 로우에 다른 회차 건이 섞여 있으면 따로 세서 오른쪽 바에 알려줘요.

## 작업 이어하기

- 파일을 올리면 그 파일의 **정산예정일(회차)** 로 작업이 자동으로 만들어지고, 서버에 바로 저장돼요.
- 정산서를 여러 번 나눠 올려도 계속 쌓여요. 같은 이름의 파일은 새로 올린 것으로 바뀌어요. 로우데이터는 회차당 하나만 남아요.
- 다시 접속하면 마지막으로 하던 회차가 자동으로 열려요. 다른 PC에서는 첫 화면의 **이어서 할 회차** 목록에서 고르면 돼요.
- 회차 검수가 끝나면 **검수 끝 · 초기화**를 누르세요. 서버에 올려둔 로우·정산서 내용을 비우고 목록에서 내려요. 저장한 검수 결과는 [검수 기록]에 그대로 남아요.

## Supabase

- 프로젝트: `woori-001's Project` (`omdyyvqkxxigilxjysbz`)
- 테이블 (모두 `gift_` 접두어라 다른 앱과 겹치지 않아요)
  - `private.gift_accounts` / `gift_sessions` / `gift_login_attempts`: 계정, 로그인 토큰(해시), 로그인 시도
  - `public.gift_runs`: 검수 실행 기록(회차, 건수, 미차감 합계, 협력점 요약, 메모, 실행자)
  - `public.gift_findings`: 검수 결과 상세
  - `public.gift_work`: 작업 중인 회차(이어하기)
  - `public.gift_work_files`: 회차별로 올린 로우데이터·정산서 내용 (필요한 칸만, 고객명은 가림)

**보안 구조**
- 모든 `gift_` 테이블은 RLS를 켜고 정책은 두지 않았어요. 그리고 `anon`·`authenticated`의 테이블 권한을 회수했어요. 그래서 브라우저 키로는 테이블을 직접 읽거나 쓸 수 없어요.
- 앱은 `gift_*` RPC 함수로만 데이터에 접근해요. 각 함수는 로그인 토큰을 먼저 확인하고, 계정 관리와 기록 숨기기는 관리자만 할 수 있어요.
- 비밀번호는 bcrypt로 저장하고, 토큰은 SHA-256 해시만 저장해요. 세션은 8시간 동안 유지되고, 사용할 때마다 연장돼요. 10분 안에 10번 틀리면 로그인을 막아요.
- 데이터를 지우지 않아요. 로그아웃은 세션 만료, 계정 중지는 `enabled=false`, 기록 삭제는 숨김(`deleted_at`), 올린 파일 빼기는 `removed_at`, 작업 끝내기는 `status=closed`로 처리해요.
- Supabase 보안 점검(advisor)에서 `rls_enabled_no_policy`(INFO)와 `security_definer_function_executable`(WARN)이 나오는데, 위 설계에서 의도한 결과예요. 같은 프로젝트의 upche 앱도 같은 방식이에요.

**주의**
- `js/config.js`에는 공개용 **publishable 키**만 넣어요. `service_role` 키나 secret 키는 절대 커밋하지 마세요.
- `.gitignore`가 `*.xls`, `*.xlsx`, `*.csv`를 막고 있어요. 고객 정보가 든 엑셀 파일이 커밋되지 않게 하려는 거예요.

## RPC 목록

| 함수 | 권한 | 설명 |
|---|---|---|
| `gift_login(p_id, p_password)` | 누구나 | 로그인. 토큰 발급 |
| `gift_logout(p_token)` | 누구나 | 세션 만료 |
| `gift_me(p_token)` | 로그인 | 내 정보 |
| `gift_change_password(p_token, p_old, p_new)` | 로그인 | 비밀번호 변경. 다른 세션은 끊음 |
| `gift_account_list(p_token)` | 관리자 | 계정 목록 |
| `gift_account_save(p_token, p_id, p_name, p_password, p_role, p_enabled)` | 관리자 | 계정 추가·수정·중지 |
| `gift_run_save(p_token, p_run, p_findings)` | 로그인 | 검수 결과 저장 |
| `gift_run_list(p_token, p_limit)` | 로그인 | 기록 목록 |
| `gift_run_get(p_token, p_id)` | 로그인 | 기록 상세 |
| `gift_run_memo(p_token, p_id, p_memo)` | 로그인 | 메모 수정 |
| `gift_run_hide(p_token, p_id)` | 관리자 | 기록 숨기기 |
| `gift_work_list(p_token)` | 로그인 | 작업 중인 회차 목록 |
| `gift_work_open(p_token, p_settle_date)` | 로그인 | 회차 작업 열기(없으면 만들기) |
| `gift_work_get(p_token, p_work_id)` | 로그인 | 회차 작업과 올린 파일 불러오기 |
| `gift_work_put_files(p_token, p_work_id, p_files)` | 로그인 | 파일 저장(같은 이름은 덮어씀) |
| `gift_work_remove_files(p_token, p_work_id, p_kind, p_names)` | 로그인 | 파일 빼기 |
| `gift_work_close(p_token, p_work_id)` | 로그인 | 검수 끝 · 초기화 (작업 닫고 올린 파일 내용 비움) |
